----------------------------------------------------------------
1.1 — PULL KYA CHEEZ HAI? (EK KAHANI SE SAMAJH)
----------------------------------------------------------------

SOCH: Tu ek notebook likh raha hai.
      Teri ek PHOTOCOPY machine hai (GitHub).

      PUSH  =  notebook ki photocopy bhejna  (tu -> GitHub)
      PULL  =  photocopy wapas mangwana      (GitHub -> tu)

SIMPLE:
      push  =  SAVE karna cloud mein
      pull  =  LOAD karna cloud se

AUR "CLONE"?
      clone =  POORI notebook pehli baar copy karna
      pull  =  sirf NAYE pages lena (jo badle hain)

----------------------------------------------------------------
1.2 — TEEN ALAG CHEEZEIN (LOG INMEIN GADBAD KARTE HAIN)
----------------------------------------------------------------

  COMMAND      KAB                        KYA KARTA HAI
  ---------    ------------------------   ------------------------
  git clone    PEHLI BAAR, naye computer  Poora repo download
  git pull     ROZ, kaam SHURU se pehle   Naye changes laata hai
  git push     ROZ, kaam KHATAM ke baad   Tere changes bhejta hai

EK AUR (advanced, baad ke liye):
  git fetch    sirf DEKHTA hai kya aaya   Download karta hai par
               par tere code ko chhoo     MERGE nahi karta
               ta nahi

  pull  =  fetch  +  merge

----------------------------------------------------------------
1.3 — GOLDEN RULE (YE KABHI NAHI BHOOLNA)
----------------------------------------------------------------

        ============================================
           SUBHA    ->  PULL     (naya lao)
           DIN BHAR ->  KAAM     (code likho)
           SHAM     ->  PUSH     (save bhejo)
        ============================================

  "PULL FIRST, PUSH LAST"

KYUN?
  Agar tu bina pull kiye push karega aur doosri jagah
  kuch badal gaya ho -> CONFLICT.
  Conflict = do logon ne ek hi line alag alag likhi.
  Git confuse ho jata hai: "kaunsi rakhoon?"

  Subha pull karne se conflict ka chance ~0 ho jata hai.

----------------------------------------------------------------
1.6 — CONFLICT: DARNA MAT, SAMJHO
----------------------------------------------------------------

CONFLICT KAB HOTA HAI?
  Tu ne line 10 badli.
  Kisi aur ne (ya tu ne doosre computer se) line 10 ALAG badli.
  Git: "Bhai, dono sahi nahi ho sakte. Tu decide kar."

CONFLICT DIKHEGA AISE:
    <<<<<<< HEAD
    const tax = 0.18;          <- TERA wala
    =======
    const tax = 0.12;          <- DOOSRA wala
    >>>>>>> origin/main

  <<<<<<<  = tera code shuru
  =======  = dono ke beech ki deewar
  >>>>>>>  = doosra code khatam

SOLUTION (3 STEP):
  1. Wo file khol
  2. Jo sahi hai RAKH, baaki DELETE kar
     (<<<<<<< ======= >>>>>>> ye 3 line BHI hatani padti hain)
  3. git add <file>  ->  git commit  ->  git push

SABSE ACHHA TAREEKA?
  CONFLICT AAYE HI NA — isliye subha pull karo.

3.2 — DO RASTE (TU CHUN)
----------------------------------------------------------------

OPTION A — TU KHUD KAR (RISK = ZERO)
----------------------------------------------------------------
  Agar tere paas koi computer hai jisme Node.js installed hai:

      npm login
      cd stream-os-engine
      npm publish --access public

  2 COMMAND. 2 MINUTE.
  Main tujhe files de doonga (zip ya repo se clone karke).

  ✅ FAIDA: Mujhe kuch nahi dena padta. Risk = 0.
  ❌ NUKSAN: Node install karna padega (agar nahi hai).

OPTION B — MAIN KAROON (EK CHHOTA TOKEN CHAHIYE)
----------------------------------------------------------------
  npm par token bana, mujhe de, main publish kar doonga.

  TOKEN KITNA TIGHT HOGA:
    Type        : Granular Access Token
    Name        : stream-os-first-publish
    Expiry      : 7 DIN (khud expire ho jayega)
    Packages    : SIRF stream-os-engine
                  ("Only select packages" chunna)
    Permission  : read + write (publish ke liye)
    Orgs        : koi nahi

  YE TOKEN KYA NAHI KAR SAKTA:
    ❌ Tera account delete
    ❌ Doosre packages chhoo
    ❌ Payment / settings badal
    ❌ 7 din baad kuch bhi (expire)

  BURA SCENARIO (agar leak ho jaye):
    Koi tera package ka naya version publish kar de.
    npm 72 ghante mein unpublish kar deta hai.
    -> Khatra hai, PAR recoverable hai.

  MERA VAADA:
    - Token main kahin permanently save nahi karoonga
    - Kaam khatam -> delete
    - Kabhi kisi aur ko nahi bataoonga
    - Publish ke baad OIDC set karenge, phir token
      KI ZAROORAT HI NAHI RAHEGI -> usi waqt delete kar dena

  ✅ FAIDA: Tere ko kuch install nahi karna. 3 minute.
  ❌ NUKSAN: Thoda sa risk (7 din, 1 package).

                 PART 8 — TROUBLESHOOTING
================================================================

"Permission denied (publickey)"
  -> deploy key add nahi hui, ya "Allow write access" nahi tick kiya
  -> check: ssh -T git@github.com

"src refspec main does not match any"
  -> koi commit hi nahi hai. Pehle commit karo.

"Updates were rejected because the remote contains work"
  -> remote par kuch hai jo tere paas nahi
  -> fix: git pull --rebase  phir  git push

"403 Forbidden" (npm publish)
  -> token expire, ya permission "read only" hai
  -> doosra token banao, "read and write" chuno

"404 PUT" (npm publish via OIDC)
  -> 99% chance: Node version purana hai
  -> fix: workflow mein node-version: "24.x"
  -> npm CLI 11.5.1+ zaroori hai; Node 22.12/22.13 bhi kaam nahi

"EPUBLISHCONFLICT"
  -> ye version pehle hi publish ho chuka hai
  -> fix: npm version patch

"You cannot publish over the previously published version"
  -> upar wala hi hai. Version badhao.

"Package name too similar to existing package"
  -> naam badlo (maine 4 free naam dhoondh ke rakhe hain)

                    PART 9 — GLOSSARY
================================================================

  repository (repo)  project ka folder + uska poora itihaas
  remote             GitHub par jo copy hai (cloud wali)
  origin             remote ka nickname (default naam)
  local              tere computer/sandbox wali copy
  commit             ek save-point (jaise game ka checkpoint)
  branch             alag alag kaam ki parallel line
  main               default branch ka naam (pehle "master" tha)
  clone              poora repo pehli baar download
  pull               cloud se naye changes lana (fetch+merge)
  push               cloud ko tere changes bhejna
  fetch              sirf download, merge nahi
  merge              do branch ka code milana
  conflict           do jagah ek hi line alag badli
  fast-forward       bina conflict ke seedha aage badhna
  HEAD               abhi tu kahan khada hai (current commit)
  staging area       commit hone wali files ki waiting room
  npm                JS packages ka store
  package            ek library jo install ho sake
  registry           npm ka server jahan packages rakhe hain
  OIDC               bina password/token ke pehchan proof karna
  provenance         digital proof ki ye code isi repo se aaya
  deploy key         sirf EK repo ke liye SSH chaabi
  dist-tag           version ka nickname (latest, next, beta)
