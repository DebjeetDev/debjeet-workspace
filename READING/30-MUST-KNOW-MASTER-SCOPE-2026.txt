PURPOSE
-------
This is the scope decision card. It prevents the false goal of knowing every
JavaScript, frontend, backend, cloud, AI, and browser topic deeply at the same
time.

CORE TRUTH
----------
No engineer remembers every API all the time. A strong engineer knows the
mental model, the common patterns, the risks, and how to find the exact API
when needed.

FOUR KNOWLEDGE LEVELS
==============================================================================

L1 — AWARENESS
  Can explain what the tool is and when it may be useful.
  Example: knows that Web Workers move work away from the main thread.

L2 — WORKING USE
  Can use the tool with official documentation and a small example.
  Example: can call an API, handle loading/error, and read its reference.

L3 — INDEPENDENT BUILDING
  Can design the data flow, write the core logic from a blank file, test
  edge cases, and debug without copying a tutorial.

L4 — PRODUCTION JUDGEMENT
  Can choose between alternatives, explain trade-offs, defend security and
  performance, review another person's code, and maintain the feature.

RULE: Current project topic = L3. Core foundation = L4 over time. Nearby
skills = L2. Distant or specialised topics = L1 until a real project needs
 them.

==============================================================================
THE BEST WAY TO LEARN EACH TOPIC
==============================================================================

  1. WHY — What real problem does this solve?
  2. TRIGGER — What sentence tells me to use it?
     "Keep matching items" means filter.
     "Transform every item" means map.
     "Many values into one result" means reduce.
     "Wait for remote data" means async/fetch.
  3. MODEL — Explain the data flow in simple English and Bengali.
  4. PAPER — Write input, output, rules, and edge cases.
  5. SMALL BUILD — Write one narrow function or feature.
  6. PROOF — Run normal, empty, invalid, duplicate, and boundary cases.
  7. REVIEW — Check readability, mutation, security, and performance.
  8. RECALL — Explain where this pattern would appear in a real product.

==============================================================================
WHAT NOT TO DO
==============================================================================

  - Do not learn every library at once.
  - Do not memorise every API signature.
  - Do not open React, AWS, AI, and Chrome APIs during a pure JS task.
  - Do not add a topic only because it looks impressive on a checklist.
  - Do not reopen a completed phase because one bonus method is unfamiliar.
  - Do not measure progress by how many topics were read; measure by what can
    be built, tested, explained, and maintained.
