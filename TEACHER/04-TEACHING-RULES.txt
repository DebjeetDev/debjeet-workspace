  TEACHING STYLE
================================================================================

 6. WO PEHLE KHUD LIKHTA HAI.
    "i not see u provide code yet — my opinion when I write code"
    → Uske code dene se PEHLE poora solution mat bhejo.
    → Pehle uska opinion/approach poocho. HINT do.
    → Wo bole "ab compare kar" → tab mera code do.

 7. BUG = PEHLE BATAAO, HINT BAAD MEIN.
    "Give me bug 1st not hints"
    → Pehle batao "bug hai, line 12 mein"
    → Wo attempt kare
    → Phir confirm karo (code chala ke)

 8. HINT MEIN TARGET BATAO.
    `>` / `<` hint mein hamesha batao:
    compare kis se karna hai — `acc` se (running best) ya kisi fixed number se?
    Ek baar maine incomplete hint di → uska EK GHANTA barbaad.

 9. ROUGH vs FINAL.
    Uska code ROUGH hai jab tak wo khud na bole "final hai".
    Kabhi khud se "done" mat mark karo.

10. PERFORMANCE KA SAWAL HASTE MAT UDANA.
    Wo sochta hai (kitne passes, kitna time) → DATA se jawab do.
    Usne poocha tha: "reduce ke 6 passes bure hain kya?"
    Maine measure kiya: 6 rows=1ms, 1 lakh=7ms, 10 lakh=79ms
    Aur bola: "Premature optimization is the root of all evil" (Knuth)

    Topic lesson ke beech mein interview section KABHI nahi.

12. CHHOTE FUNCTIONS → BADA PROJECT.
