PHASE 4 — FUNCTIONS DEEP (100% DONE)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

1.  CLOSURE — Private state
    Jab ek function apne andar ke variables ko yaad rakhta hai,
    aur bahar se koi unhe chhoo nahi sakta.

        function createSubscriptionEngine(secretPin, initialPlans) {
            const MAX_ATTEMPT = 3;
            let prices = initialPlans;      // PRIVATE
            let attempts = 0;               // PRIVATE

            return { /* methods yahan */ };
        }

    Analogy: Ek locker. Andar paisa hai. Bahar se sirf PIN se khulta hai.
             Locker ke andar haath dalne ka koi raasta hi nahi.


2.  GUARD CLAUSE — Pehle check, phir kaam
    Function ke shuru mein hi galat input ko rok do.
    Happy path sabse aakhir mein aata hai.

        if (attempts >= MAX_ATTEMPT)  return { ...403 };
        if (pin !== secretPin)        return { ...401 };
        if (!Number.isFinite(price))  return { ...400 };
        // abhi happy path

    Junior aakhir mein sochta hai. Senior pehle rokta hai.


3.  RESULT PATTERN — Hamesha ek hi shape
    Har method chahe success ho ya fail, ek HI tarah ka object dega.

        Success:  { status: 200, ok: true,  data: ... }
        Fail:     { status: 400, ok: false, error: "..." }

    Isse SonarLint ki warning bhi khatam ho jati hai:
    "refactor this function to always return the same type"


4.  DEFAULT PARAMETERS
        function engine(secretPin = "7788", initialPlans = [199, 499, 999]) {}

    IMPORTANT: Default tabhi chalta hai jab kuch NA bheja jaye (undefined).
               Agar koi null ya 123 bhej dega, default KAAM NAHI KAREGA!
               Isliye guard clause ALAG se lagana zaroori hai.


PHASE 5 — ARRAYS DEEP (Step 1 se 4 DONE)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

5.  ARRAY LITERAL + Array.isArray() + .length + .at()     [STEP 1]

        const prices = [199, 499, 999];
        prices.length       // 3
        prices.at(0)        // 199   (pehla)
        prices.at(-1)       // 999   (AAKHRI - modern ES2022+)
        Array.isArray(x)    // true ya false

    Zero-based indexing: pehla item index 0 pe hota hai.


6.  SPREAD OPERATOR — Bina mutate kiye add karna            [STEP 2]

    MUTATING (khatarnak):
        prices.push(newPrice);      // asli array badal gaya

    NON-MUTATING (company standard):
        prices = [...prices, newPrice];   // NAYA array bana

    Analogy: Original marksheet pe pen se mat likho.
             Photocopy nikalo, uspe likho.
             (React aur Redux mein .push() karna = bug!)


7.  .map() — Har element ko badalna                          [STEP 3]

        prices.map((p) => p + 50)

    Rules:
        - Jitne items andar, utne hi bahar (length kabhi nahi badalti)
        - Original array kabhi change nahi hota
        - Hamesha NAYA array return karta hai

    Real use: applyTaxToAll() mein har price pe tax joda.


8.  .filter() — Chhaantna (Chai ki chhanni)                  [STEP 4]

        prices.filter((p) => p >= 500)

    Rules:
        - Jo condition TRUE karega, wahi naye array mein jayega
        - Length KAM ho sakti hai (ya zero - khali array [])
        - Original array kabhi change nahi hota

    Real use: getPremiumPlans() mein sirf mehnge plans rakhe.

PART B — THE 4 METHODS (Contract)
------------------------------------------------------------------------------

  getLatestPlan()              -> AAKHRI plan ka price          -> 200
  addNewPlan(pin, planPrice)   -> PIN check karke naya plan add  -> 201
  getPremiumPlans(minPrice)    -> minPrice ya usse mehnge plans  -> 200
  applyTaxToAll(taxAmount)     -> har price pe tax jodo          -> 200


  SECURITY RULE (Brute-Force Lock):
      - 3 baar galat PIN = permanent lock (status 403)
      - Lock ke baad SAHI PIN bhi kaam nahi karega
      - Sahi PIN milte hi attempts = 0 reset ho jata hai
      - Lock sirf addNewPlan ko rokta hai, baaki methods chalti hain

                  prices = [...prices, planPrice];

          SAHI:   if (taxAmount < 0)  return error;
