## Decision

The new root-level Real Path is the active career route. The `READING/` folder remains a reference library and historical record. It is not deleted and it is not treated as one giant mandatory checklist.

## Why this is necessary

`READING/10-FULL-SYLLABUS.txt` contains a broad long-term Bible with:

- Internet and terminal material
- HTML/accessibility
- full CSS
- Tailwind and shadcn
- 3D, GSAP, and animation
- JavaScript phases 1–10
- React and Next.js
- Node and Express
- MongoDB and PostgreSQL
- Redis, queues, WebSockets, and file storage
- testing and CI
- AI, RAG, agents, voice, and autonomous tooling
- DSA, system design, DevOps, branding, and job hunting

That breadth is useful as a reference, but following every unchecked marker linearly would create an endless route. The old file also contains historical status and older project-gate wording.

## Conflicts resolved by the final path

1. J3 functional acceptance is complete, but independent student authorship is pending; Pub/Sub is not repeated as a later J5.
2. J3-A independent rebuild is deferred and non-blocking; J4 is the immediate active project.
3. Async retry/timeout/concurrency is promoted because it directly supports backend reliability.
4. Stream-OS research is retained as background and can feed the later StreamAPI product.
5. Memoize/LRU is useful but not allowed to block the main backend route.
6. Testing is cross-cutting, not postponed to the end.
7. Applications begin after a credible live backend project, not only after every future topic is finished.

## Synchronization rule

Do not mass-edit old Reading checkboxes to pretend that the entire old Bible is complete. When a new active module is completed, record evidence in the active project folder, this continuity pack, and the requested status files. Preserve historical checklists honestly.
